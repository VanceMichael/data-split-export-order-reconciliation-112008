# 跨境订单的分箱采集与货值差异复核

这里是可离线启动的合成上游与本地复核服务，所有编号、时间和凭据都用于联调。

## 本地运行

使用 Node.js 22.23.4。项目只使用随 Node.js 提供的运行库。

```sh
npm start            # 终端 1：合成来源，http://127.0.0.1:4173
npm run start:review # 终端 2：复核服务，http://127.0.0.1:4174
npm test
```

不同终端分别启动服务和执行独立来源测试。来源默认地址为 `http://127.0.0.1:4173`，可通过 `SOURCE_PORT` 设置端口，也接受通用的 `PORT`，同时设置时以 `SOURCE_PORT` 为准。`GET /health` 用于确认来源服务已就绪。来源使用进程内演练时钟，启动时处于 `sale`。用 `PUT /_source_clock?step=boxed` 推进到下一阶段，`GET /_source_calls` 查看本实例收到的业务请求。可查阶段为 `sale`、`boxed`、`split`、`partial-refund`、`late-proof`、`replacement`。重启服务会重置时钟和请求记录。预置的源端回执按演练阶段出现，和本地应用是否已处理某次回执是两回事。

复核服务用 `APP_PORT`（默认 4174）、`SOURCE_BASE`（默认 `http://127.0.0.1:4173`）、`ACCOUNTS`（默认 `west,south`）配置。启动时自动采集一轮；来源未就绪可稍后 `POST /collect` 再采。

`npm test` 核对可访问的上游响应、合成资料，以及复核服务在全部演练阶段的行为。

## 演练流程

每推进一个阶段采集一轮，再从任一箱查复核依据：

```sh
curl -X PUT 'http://127.0.0.1:4173/_source_clock?step=split'
curl -X POST http://127.0.0.1:4174/collect
curl http://127.0.0.1:4174/boxes/B5-0
```

| 阶段 | 看点 |
| --- | --- |
| `sale` | 封箱锁定金额依据；套件跨箱的分币合计等于成交金额 |
| `boxed` | 第 2 页空页标记：旧装箱事实保留，标待补页，不当缺装 |
| `split` | B1-0 拆出 B1-1/B5-0，旧事实按封箱实例保留，新箱有自己的标签 |
| `partial-refund` | R1 指明品件 → 未交运的 B5-0 重新核价；R2 归属不唯一 → 相关货值挂起，B3-0/B4-0 独立可复核 |
| `late-proof` | 晚到的 H9 核定出 B1-0 已交运，保留旧复核单并列差额；重贴的 B5-0 不继承已接收状态 |
| `replacement` | 订单更正 C7 认可 PLATE-2，未交运的 B2-0 重出；B3-0 显式清空撤箱 |

## 复核接口

- `POST /collect` 跑一轮采集，返回各来源页的读取结果与是否完整。
- `GET /boxes` 各箱一览：生命周期、可否交运、币种货值、挂起与原因。
- `GET /boxes/{pack}` 单箱复核视图：成交版本与当次分配凭据（`deals`）、装箱迹线与标签（`trace`、`tags`）、币种和货值（`values`）、可否交运及原因（`shippable`、`reasons`）、待核实的退款与货代签收（`refunds`、`handovers`）。
- `GET /boxes/{pack}/history` 历史复核单：每版的原因和与上一版的币种差额。
- `GET /refunds` 各退款的归属核定：重新核价、已交运箱差额、挂起或待核实。
- `GET /orders/{account}/{order}` 订单视图：行、分配凭据、各品件所在箱、缺装或待核实。
- `GET /collections` 各轮采集记录，可回查哪一页缺片或为空。

## 复核规则

- 订单行号只在店铺和订单内有效；套件比例与金额舍入以销售时的版本明细为准：先舍去不足一分的余数，再按未舍位余数从大到小分配，仍相同按套件清单顺序，分币差额不造成总额变化。
- 替换件要有订单更正或订单下的补发指示认可，否则该箱标未获订单认可，不可交运。
- 分页缺片、来源空页标记、明确清空是三种不同结果：不完整采集保留旧事实并标待补页；只有带 `cleared` 的显式清空才算撤箱；完整采集后无事实且无轨迹解释才标缺失待核实。
- 封箱时锁定复核单金额依据；尚未交运的箱子遇到订单更正或退款可重出新版；已交运的箱子保留旧复核单，只列出对应差额和原箱。
- 退款按平台明确归属的行、数量和品件核定；目标对应多个封箱时相关货值挂起，保留其他独立的可复核箱。
- 货代签收以交接凭据为准：接受时间落在封箱有效期内且实物标签与当时一致，才算该次封箱交运；重贴、拆分之后的新箱不自动继承原箱已接收状态，对不上的凭据留待人工核定。

## 来源约定

`/shops/orders?account=west` 与 `/shops/orders?account=south` 提供各店铺订单、套件销售版本、金额变动及明确的退款指向，`minorAmount` 用币种最小单位。 `/shops/kits` 的 `weight` 是套件各品件的成交金额比例按整数权重表达。按可核对的销售行与实际所装品件分配，先舍去不足一分的余数，再按未舍位的余数从大到小分配，仍相同则按套件清单里的品件顺序。退款若映射到多个实际封箱且平台未说明对应品件，应查询人工审核。
仓库 `/warehouse/closeouts` 列出装箱实例的演变， `/warehouse/manifest?page=1` 给出封箱实例与零件， `blank` 表示此页没有可读条目仍待补，只有带 `cleared` 的显式清空能证明某个箱已撤。货代 `/forwarder/handover` 使用见证的封箱号和实物标签接收，`at` 为实际接收时间，`receivedAt` 是凭据到达时间。
